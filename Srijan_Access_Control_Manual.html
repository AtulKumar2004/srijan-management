This document serves as the authoritative User Manual & Access Control Specification for the Srijan Youth Festival Management System. It outlines architectural hierarchy, module permissions, page access privileges, and data creation/editing rules for all user roles across the platform.

1. Role & Hierarchy Architecture

The system enforces a strict 6-tier role ranking model (`ROLE_RANK`) designed to segregate administrative capabilities, program execution, volunteer mentorship, and mentee participation.

Rank Role Identifier User Title Core Responsibilities & Scope
4.0 admin Super Administrator Full platform control. Manages system configurations, global guest pools, all programs, outreach tasks, and user promotions across all ranks.
3.5 program_manager Program Manager Oversees designated festival programs. Manages session schedules, coordinates volunteers, reviews mentee follow-ups, and analyses program metrics.
3.0 volunteer Volunteer / Mentor Frontline mentor. Records daily session attendance, manages mentee groups, conducts outreach follow-up calls, and submits progress remarks.
2.0 participant Participant / Mentee Registered festival attendee. Views enrolled program sessions, personal profile, and individual attendance records.
1.0 guest Guest User Newly onboarded registrant awaiting administrative verification. Restricted strictly to profile viewing until verified.
0.0 outreach Outreach Contact External student/contact pool entry used for follow-up coordination and call logging.

4. Role Transition & Promotion Safeguards

To preserve organizational security, role promotions managed via /api/roles/change enforce three inviolable authorization rules:

  1. Subordinate Rank Restriction: An actor cannot modify the role of any user whose current rank is equal to or higher than their own (targetRank >= actorRank). For example, a Program Manager cannot edit another Program Manager or an Admin.
  2. Guest Verification Monopoly: Newly registered users in the guest tier can only be verified and assigned operational roles by an Admin.
  3. Volunteer Promotion Cap: Volunteers cannot promote participants to Volunteer or Admin status; such requests must pass through administrative review workflows.

5. Key Operational Workflows

A. Program & Session Setup Workflow

1. Admin creates a Program specifying age criteria, description, and associated temple.
2. Program Manager accesses the program and creates specific time-slotted Sessions.
3. Participants and Volunteers enroll or get assigned to the program.

B. Daily Attendance & Mentorship Workflow

1. During festival sessions, Volunteers open the session attendance roster on their mobile devices.
2. Volunteers mark presence (`Present`, `Absent`, `Excused`) for their assigned mentees.
3. Attendance instantly reflects on the mentee's profile and updates global analytics on the Program Manager dashboard.
